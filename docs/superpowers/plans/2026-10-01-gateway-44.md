# Phase 44: VGP v1 gateway connector — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `type: gateway` account trades futures and options live through any VGP v1 gateway
(`docs/superpowers/specs/2026-10-01-vgp-v1-wire.md`), with the same engine events as every other
broker: a submit is accepted, filled (partly or whole), cancelled or rejected exactly once, a fill
is never lost or doubled across a disconnect, and the kill switch never blocks a flatten.

**Architecture (package `com.qkt.connector.gateway`, which imports no `app`/`cli`/`risk`/`dsl`/
`backtest`):**
- **`GatewayClient`** — REST: health, account, positions, orders, deals, submit (idempotent
  resend on timeout/`503`, `422`/`423` refusals), cancel, close.
- **`GatewaySymbols`** — the exact venue code ↔ qkt symbol map, built from `GET /v1/instruments`:
  qkt symbol = account prefix + code with `-` written `_` (as `OptionSymbols`). Futures codes keep
  their `_`, so the reverse direction is a lookup, never a character swap. Unknown symbols refuse.
- **`GatewayEventTranslator`** — the one place engine events are built from wire objects:
  - an `order` event maps to `OrderAccepted` once per order, `OrderCancelled`, or `OrderRejected`;
  - a `fill` maps to `OrderPartiallyFilled` until the order's cumulative quantity reaches its
    quantity, then `OrderFilled`; a `fill_id` already booked is dropped;
  - typed costs map to `VenueCost`; a `settlement` maps to `ContractSettled` (expiry is not a fill).

  Strategy attribution comes from the submit (client order id → strategy), and after a restart
  from the orders the engine hands back (`recoverPendingOrders`).
- **`GatewaySession`** — one per account, shared by every strategy trading on it (portfolios): one
  client, one stream, one translator. Each strategy's thin `GatewayBroker` attaches with its bus;
  an order's events go to its strategy, a `settlement` to every strategy. Expiry is a contract-level
  `settlement` event; the engine (`ContractSettlement`) closes each strategy's own holding at its
  price and shares the venue's costs by holding.
- **`GatewayStream`** — the WebSocket: open with `since` (exclusive), drop `seq <=` the last
  processed, detect `reset` or a `stream` change and call the resync, and reconnect with backoff
  (1 s doubling to 30 s), publishing `ConnectionChanged`.
- **`GatewayBroker`** — `Broker`:
  - `submit` maps Market/Limit/Stop/StopLimit to `WireSubmit`, with `reduce_only` only when the
    order strictly reduces the current position, and sends it off the engine thread; refusals
    become `OrderRejected`;
  - `cancel` (VGP v1 has no modify); open positions and account equity come from the session;
  - resync (start, reset): working orders, positions, and deals since the last booked fill, with
    missing fills booked by `fill_id`.
- **`GatewayConnector`** / **`GatewayTradingAccount`** — settings `gateway_url`, `api_key` (`env:` /
  `file:`), `expected_adapter`, `expected_account_login`, `expected_trade_mode`, `http_timeout_ms`,
  `retry_attempts`. `verify()` refuses a gateway whose `protocol` is not `vgp1` or whose identity
  differs from the expected values. Several strategies may share an account. Registered through `ServiceLoader`. Product types: FUTURE,
  PERPETUAL, SPOT, and a new OPTION.
- **Market data and routing (task 5):** `quote` events become ticks (`GatewayMarketSource`); live
  futures routes wrap the gateway broker in `ContinuousContractBroker` as in backtest; option quotes
  feed a live chain snapshotter, so structures select from live snapshots.

## Global constraints

- No CFD change: MT5 and Bybit connectors untouched; architecture test green; golden pins green.
- Files ≤ 200 lines; KDoc; every behaviour tested against `MockWebServer` (REST and WebSocket)
  implementing the wire spec.

## Review focus

- A fill replayed after a reconnect, and a fill arriving before the submit's REST reply.
- Cancel racing a fill (`DELETE` answers `filled`).
- A `reset` mid-run: the deals since the last booked fill are booked once.
- Kill switch: a reducing order passes (`reduce_only`), an opening one is rejected with the reason.
- Identity mismatch at `verify()`: never trades.

### Task 5: market data (quotes → ticks), live futures/options routing, chain snapshotter

Design (decided before coding):
- **Quotes leave the event log.** The event log is exactly-once (orders, fills, settlements); quotes
  are latest-wins and high volume, and replaying them after a reconnect is wrong. The wire spec moves
  them to their own WebSocket, `GET /v1/quotes?symbols=<code>,<code>` (live only, no `seq`), and drops
  `quote` from `/v1/stream`.
- **`GatewayMarketSource`** (the account's `marketData`): `liveTicks(symbols)` opens that socket and
  emits one tick per quote, priced at the mark (the backtest option convention) or else the mid of a
  two-sided quote, with the quote's sides; a one-sided quote without a mark emits nothing. A fed root
  `OPTIONS:<V>.<R>` subscribes every listed contract of the root.
- **Live chain snapshots.** A `ChainSnapshotter` samples each root's last quote per contract at the
  feed's window boundaries and appends a `book` snapshot to the same `ChainSnapshotStore` backtests
  read, so `ChainView` (structures) and `CHAIN:` metrics work live from the history live builds.
- **Live futures:** `SessionBrokers` routes a continuous futures stream through
  `ContinuousContractBroker` over the gateway broker, as backtest does over the simulator.
