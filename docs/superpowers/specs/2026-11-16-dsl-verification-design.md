# DSL verification — design

**Status:** design, 2026-11-16. Built from three read-only audits of `origin/dev` (1b6580924): grammar and
semantics, indicator and math accuracy, execution and parity. Their reports are the evidence; this document is the
plan.

## 1. Why

Line coverage says a line ran, not that the answer was right. qkt is at 98.6 % lines / 82.8 % branches, yet the
audits found:

- **One** of 59 indicators is checked against an independent reference (SMA, indirectly). The rest are checked
  against hand-worked 3–6 bar sequences; nothing runs EMA/RSI/MACD/Bollinger at default periods or past 40 bars.
- **No** strategy with an exit (bracket, OCO, OTO, STACK, STACK_AT, EXIT AFTER, trailing) has its trade tape or P&L
  computed by anything other than qkt itself. The release audit recomputes P&L from qkt's own fills.
- Live bugs and silent differences: unguarded division by a zero price in three indicators (now reachable: event
  contracts price at 0); a rule that double-fires across an Undefined bar; take-profit equal to entry when the stop
  distance is 0; no margin level or stop-out in paper/mt5-sim backtests; `volumeMax` never enforced in paper; STACK
  spacing ≤ 0 accepted; LATCH, SCHEDULE and CROSSES state lost on restart.

The goal: a person can put money behind a `.qkt` file because every construct, number and path it can produce is
pinned by a test whose expected value was computed independently of qkt.

### Goals

1. Every DSL construct parsed, evaluated and executed by tests that assert exact values.
2. Every indicator and function matches an independent reference within a stated tolerance, at realistic periods
   and on real data, including edge series.
3. Every order, position and P&L path the DSL can produce is checked against an independent oracle.
4. Restart, multi-stream and cross-venue behaviour pinned.
5. The suite is the gate: a change that alters any verified result fails CI until the expectation is updated on
   purpose.

### Non-goals

- Re-proving venues' own behaviour (the gateway contract kit and attestation do that).
- Replacing line coverage (the coverage program continues separately).

### Anti-goals

- An oracle that shares code with qkt (it would agree with qkt's bugs).
- Expected values regenerated by running qkt ("golden snapshots" alone are not verification).
- Silent behaviour changes: every bug fix that changes trades names the golden and corpus diffs it causes.

## 2. Architecture

Three independent oracles, one Kotlin harness each, under `src/test/kotlin/com/qkt/verification/` (tests named
`*VerificationTest`, so they never collide with the coverage program's test files).

| Layer | Oracle | Lives in | Checked in |
|---|---|---|---|
| Indicators and functions | Python, pinned TA-Lib / pandas / numpy / scipy | `verification/oracle/indicators/gen.py` | JSON fixtures per indicator × series |
| Strategy execution | Python `Decimal` reference engine written from the docs (fills, brackets, sizing, costs, settlement) | `verification/oracle/engine/` | per-scenario expected trade tape + P&L |
| Grammar and semantics | Table-driven Kotlin cases with hand-derived expected values | `src/test/.../verification/semantics/` | the cases themselves |

Rules:

- Oracles never import qkt code; fixtures are regenerated only by an explicit `make verification-fixtures`, and
  a fixture diff is reviewed like code.
- Each harness has a completeness test: every registered indicator, every DSL keyword and every order type must
  appear in the verification set, or the build fails naming what's missing. New features can't skip verification.
- Tolerances are stated per group: exact for decimal arithmetic, 1e-9 relative for recursive indicators, 1e-7 for
  square-root based ones.
- Scenario data: real XAU 1h and BTC 1m (with volume), plus synthetic edge series (flat, gap, zero price, huge and
  tiny magnitudes, single bar, period > data).

## 3. Slices (each its own PR, ordered by money risk)

| # | Slice | Contents |
|---|---|---|
| 1 | **Live-risk bug fixes** | zero-price guards (Skew, VarianceRatio, SessionMomentum); rule edge across Undefined; RR target with zero stop distance and RISK sizing with zero distance (refuse with a reason, never throw out of a rule); STACK spacing ≤ 0 refused at compile; `volumeMax` enforced in paper; each with a regression test and its golden diff stated |
| 2 | **Indicator oracle** | `gen.py`, fixtures for all 59 indicators + 16 functions on 3 real and 6 synthetic series, `IndicatorVerificationTest` (`@TestFactory`), completeness test; decide and document Bollinger population vs sample, flat-market sentinels, warmup table corrections |
| 3 | **Execution oracle, tranche A** | reference engine for market/limit/stop entries, bracket/OCO exits incl. same-bar stop+target (long and short, both fill modes), sizing incl. lot quantization through `.qkt`, costs (spread, commission) |
| 4 | **Execution oracle, tranche B** | OTO, STACK, STACK_AT, EXIT AFTER, trailing, composite collisions on one tick, multiple rules same bar |
| 5 | **Margin and stop-out** | free-margin gate and stop-out level in paper/mt5-sim (a design note first: it changes trades) |
| 6 | **Semantics table** | every construct × Undefined/warmup/ties/precedence/division by zero; DEFAULTS precedence on emitted orders; POSITION/ACCOUNT reads end to end |
| 7 | **Restart** | LATCH, SCHEDULE, CROSSES and slot-book persistence, each proven by a stop-and-restart test |
| 8 | **Currency and costs** | non-USD accounts, two-hop crosses, swap across holidays, funding reversal, maker fees |
| 9 | **Event contracts** | EventExpiry unit tests, void/fractional outcomes, NO-side settlement, resting orders at expiry, maker fee |
| 10 | **Parity, made independent** | BacktestLiveParityTest asserts P&L and positions; the oracle tapes double as the live attestation expectations |

## 4. How "nothing existing breaks" is kept

- Slices 2–4 and 6–10 add tests only, except where a test exposes a bug; that fix is its own PR with its golden and
  corpus diffs listed.
- Slice 1 and slice 5 change behaviour on purpose; each PR lists every changed golden trade and why the new one is
  right.
- `DslCorpusPinTest`, `GoldenBacktestTest` and the release proofs keep running; they become the second line, the
  oracles the first.

## 5. Delivery

Workers build slices in parallel where files don't overlap (1 + 2 + 6 can run together); each PR passes the full
build, the coverage gate and its own verification tests before merge, and is reviewed against the oracle by the
orchestrator.

## 6. Open questions

1. Bollinger bands: switch to sample standard deviation to match `stddev` (changes trades), or document population?
   Recommended: keep population (TA-Lib and most platforms use it) and document it, plus a test that pins the
   relationship.
2. Flat-market RSI/Stochastic: keep 50 (documented) or match TA-Lib's 0? Recommended: keep 50 and document it;
   the oracle fixture encodes qkt's documented convention for that one case.
