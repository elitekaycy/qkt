# Public-readiness audit — 2026-07-30

## Provenance

- **System under audit**: qkt working tree at `b5287ceb` (branch `fix/861-risk-env-vars`, superset of `dev` HEAD `5db7c6b4`), plus the published docs site, GitHub releases, and open issue backlog.
- **Framing questions**: (1) Can third-party people start using qkt without issues? (2) Can the owner trade own + investor capital on it without engine-level risk (DSL not doing what it says, backtest lying about live)?
- **Method and scale**: 9 dimensions (DSL correctness, backtest/live parity, money safety, state & recovery, error handling/silent failure, testing-of-claims, concurrency, public onboarding, driver-level release/docs checks) — 8 finder agents + driver; every Critical/High finding adversarially verified by an independent refuter agent reading the code (10 verifier agents). The public-onboarding finder **executed** the documented commands against the built binary (0.47.1, sha 2554a31a); its failures are reproduced, not inferred.
- **Tally**: ~75 findings raised → after verification: **5 Critical, ~23 High confirmed**; 9 findings downgraded; 2 refuted outright (kept below in Dismissed). Prior-audit fixes spot-checked and confirmed real (#436 trailing re-arm, #887 warmup rebuild, #716/#718/#720 closure provenance, persistence-failure halt).

## Verdict

**Q1 — public launch for third parties: NO.**
The documented onboarding path is broken end-to-end, reproduced by execution: the first strategy in QUICKSTART fails to parse (braceless `BRACKET`), the first backtest command exits 2 on missing `--from/--to`, `--report` is a dead flag silently swallowed (`Args.kt` ignores unknown flags), the shipped sample data cannot produce one trade, both documented live strategies fail to compile, and a fresh `qkt create template` scaffold pins Docker image `v0.47.1` that was never published. Separately, the latest release (v0.47.0, 2026-06-15) is 386 commits behind — a user installing "latest release" gets code from before every institutional-audit fix. A newcomer cannot succeed today regardless of engine quality.

**Q2 — own + investor capital: NOT YET — engine core is strong, but the exit/emergency paths have confirmed Criticals.**
The shared-pipeline claim is genuinely enforced at the paper level (full-state parity tests across trailing/GTD/CLOSE/RESIZE/latch/stack/halts; zero mocked-behavior tests in the whole suite; determinism and tick-fill byte-identity test-pinned). But adversarial verification confirmed: a venue-rejected exit is terminal with no retry and no re-arm (a CLOSE-rule-only strategy — a deployed pattern — has no stop at any layer); every flatten path except the operator kill-switch opens counter-positions on hedging accounts, **including the automated portfolio drawdown de-risk**; a degraded gateway can double-book a close (phantom reversed position, double realized PnL) and stall all order flow for the whole daemon behind 5 stuck resolver callbacks; the risk-halt cancel sweep is fire-and-forget; and the live book-risk layer — now sizing 14 live sleeves — has zero test coverage and two confirmed live≠backtest math divergences. These are exactly the paths that run on the worst day.

**What this audit did NOT find**: fund-loss bugs in the core tick→signal→risk→fill pipeline. The 2026-07-11 P0s are genuinely fixed. The confirmed problems concentrate in (a) rejection/ambiguity/restart edges of live execution, (b) the newest money features (book-risk, per-strategy caps, OF BOOK) wired live without parity or test coverage, and (c) the entire public-facing surface.
